\section{Team organisation}
\label{sec:team}

The team has three members, and each owns whole stacks
(\cref{tab:team}). Mikael built the Azure cluster and the basic stack
first. The remaining stacks were then split so that nobody waits for
anybody else.

\begin{table}[htbp]
  \centering
  \caption{Ownership of the work.}
  \label{tab:team}

    \toprule
    Member                  & Owns \\
    \midrule
    Mikael Rodriguez        & Azure cluster, basic stack, stats stack \\
    Bernat Ventura          & app stack \\
    Víctor Martín Castilla  & security review and fixes, atenea stack, report \\
    \bottomrule
  \end{tabular}

All the work lives in one shared GitHub repository, with one folder per
stack. Larger changes reached the main branch through pull requests, so
another member reviewed them before they were deployed. Small fixes
after a deploy went straight to main. Laptops are only the development
environment: each member runs their stack locally with its local Compose
file, and the production file is what gets deployed to the Swarm.

A few conventions let stacks built by different people fit together:
\begin{itemize}
  \item \textbf{Images:}
        \texttt{ccds-project.duckdns.org/<stack>-<service>:<version>},
        built by a script in the stack's folder, with the version raised
        on every change.
  \item \textbf{Networks:} public services join the shared \texttt{proxy}
        network under an alias such as \texttt{app-core} or
        \texttt{atenea-moodle}. Everything else stays on the stack's own
        network.
  \item \textbf{Secrets:} files in \texttt{<stack>/secrets/}, which git
        ignores, and Swarm secrets with a version in the name, such as
        \texttt{app\_db\_password\_v1}, raised when a file changes.
  \item \textbf{Data:} each stack keeps its shared data in its own folder
        of \texttt{/srv/nfs}.
  \item \textbf{Addresses:} the app and Moodle have their own
        subdomains, \texttt{app} and \texttt{moodle} under
        \texttt{ccds-project.duckdns.org}, and Grafana lives under
        \texttt{/grafana/} on the main domain.
  \item \textbf{Branches and language:} \texttt{build/<stack>},
        \texttt{fix/<topic>} and \texttt{docs/<topic>}, and English for
        code, documentation and commits.
\end{itemize}
